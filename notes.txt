    -> To Construct Our Own Datacenter inside Azure Cloud we need VNET Service 

    -> Azure Virtual Network - VNET 

        -> A Virtual Network (VNET) in Azure is a foundational service that enables you to 
        "build your own private network" in the Azure cloud. 

        -> VNET lets you launch AZURE resources (servers, databases, applications etc) in a 
        logically isolated virtual network that you define.

            -> https://www.akamai.com/site/en/images/article/2023/akamai-public-private-cloud.png

            -> https://images.netcomlearning.com/cms/images/virtual-private-cloud.jpg

        -> NOTE: Having VNET is similar to having your own data Center inside AZURE

        -> VNET is a service that lets customers(IBM) provision a logically isolated 
        section of the AZURE Cloud where you can launch AZURE resources(Servers) 
        in a VIRTUAL NETWORK that you define.

        -> NOTE: VNET forms the backbone for cloud infrastructure to build any applications


        -> VNET Allows Azure resources like 

            -> Virtual Machines 

            -> Database 

            -> Kubernetes Cluster 

            to communicate with each other, the internet and on-Premise network 

        
        -> Think of a VNet like a company office network, but inside Azure cloud.

            -> In an office network:

               -> Employees connect to Routers 

               -> Systems communicate internally (LAN)

               -> Security rules to control access 

            -> Similarly In Azure:

                -> VM's connect to VNET 

                -> Subnets divide the Networking
                
                -> Route Tables will manage traffic routing 

                -> Network Security Groups like Security rules in Firewalls 

        -> Without Vnet 

            -> Servers cannot communicate
            -> Applications cannot connect to databases
            -> Security cannot be controlled
            -> Internet connectivity cannot be managed

        -> NOTE: VNet is the foundation of Azure infrastructure.
    
    
    -> Azure Virtual Network - VNET - Components

        -> VNet 

            -> An Azure Virtual Network (VNet) is the foundational building block 
            for your private network in Microsoft Azure.

            -> This creates main private network

        -> Subnets (Subnetting)

            -> Subnets enable you to segment the virtual network into 
            one or more sub networks and allocate a portion of the virtual network's address

            -> Web Subnet, App Subnet & DB Subnet 

            -> This Organizes infrastructure, improves security and isolate workloads

        -> Address Space (CIDR Block)

            -> CIDR (Classless Inter-Domain Routing) is a method for allocating IP addresses

            -> Subnets are created using classless internet domain routing (CIDR) blocks 
            of the address space that was designed for the Virtual Network(VNet).

            -> This helps in dividing the VNet efficiently 

    
        -> Route Tables 

            -> An Azure Route Table contains a set of custom rules (User Defined Routes) 
            that dictate where network traffic is directed within your Virtual Network. 
            
            -> Azure automatically assigns system routes to every subnet, 
            but you can override these by creating a custom route table and 
            associating it with specific subnets.

            -> This helps in directing the traffic properly 

        -> Network Security Groups (NSG)

            -> A Network Security Group (NSG) in Azure acts as a virtual firewall, 
            filtering inbound and outbound network traffic to and from Azure resources. 
            
            -> It contains security rules that allow or deny traffic based on IP address, 
            port, and protocol, helping to secure your virtual networks.

            -> This acts like a Firewall 

        -> Public IP Address

            -> Public IP addresses enable Azure resources to communicate to internet 
            and public-facing Azure services.

            -> This is for internet(www) communication

        -> Private IP Address

            -> Azure Private IPs enable secure, internal communication between 
            Virtual Machines (VMs), load balancers, and on-premises networks 
            without exposing resources to the internet. 
            
            -> They are drawn directly from the address space of your 
            Virtual Network (VNet) subnet.

            -> This is for intranet(local) communication

        -> DNS (Domain Name Service)

            -> Azure DNS manages and resolves domain names in the virtual network 
            without the need to configure a custom DNS solution.

            -> This is for ip translation to names. 

        -> Azure Network Interface Card - NIC

            -> In Azure, a Network Interface (NIC) is a "crucial" resource that connects a 
            Virtual Machine (VM) to a Virtual Network (VNet), enabling communication 
            with the internet, other Azure services, and on-premises networks. 

                -> https://blog.cloudtrooper.net/wp-content/uploads/2023/01/image-2.png?w=607

            -> Each NIC acts as a virtual network adapter, allowing for IP configurations 
            (private/public, static/dynamic), association with Network Security Groups (NSGs) 
            for traffic filtering, and even multiple NICs per VM for advanced connectivity. 

            -> This is for connecting VMS to VNET Subnet

    -> NOTE: Subnetting In VNET 

        -> The smallest supported IPv4 subnet is a /29 and the largest is a /2 

        -> Allowed Subnetting Size is /2 to /29 

        -> https://media.licdn.com/dms/image/v2/C4D22AQHUisiaMLb_2A/feedshare-shrink_800/feedshare-shrink_800/0/1674986594079?e=2147483647&v=beta&t=j71G5D_ciVaSIebs1hMlzWd5FKezdll6XroJihdrXl8

            -> /20: 4096 IP addresses

            -> /22: 1024 IP addresses

        -> NOTE: Most of the times we see /16 for VNET 

        -> NOTE: Azure reserves exactly 5 IP addresses in every subnet 
        for internal protocol conformance and Azure service usage. 
        These IPs cannot be assigned to your Virtual Machines (VMs) or resources.

            -> First IP: Network address.
            -> Second IP: Default gateway used by Azure.
            -> Third & Fourth IPs: Mapped to Azure DNS IP addresses 
            -> Last IP: Network broadcast address

            -> NOTE: Say our subnet is 10.0.0.0/20 

                -> 10.0.0.0 (Reserved for Network address)
                -> 10.0.0.1 (Reserved for gateway)
                -> 10.0.0.2 (Reserved for Azure DNS)
                -> 10.0.0.3 (Reserved for Azure DNS)

                    -> 10.0.0.4 (usable start)
                    .
                    .
                    .
                    -> 10.0.15.254 (usable end)

                -> 10.0.15.255 (Reserved for Network broadcast)

            It operates like a physical hard drive but is fully virtualized, 
            allowing for seamless attachment, detachment, and

        -> When you provision a Virtual Machine in Azure,

            -> Data Disk: Attached to the VM to specifically store application data.

    -> Security For Virtual Machines

        -> When we are talking about increased security, what we want to focus is 
        placing Virtual Machines that holds Sensitive Data in Private Servers 

            -> A Virtual Machine without Public IP is private 

            -> A private VM cannot be Accessed From Internet,
            can only be Accessed in intranet

        -> NOTE: Making VM Private has some issues 

            -> We cannot serve traffic to private instances as there is no
            route to internet

            -> We cannot Access Virtual Machines that are Private 

        -> NOTE: Solution for above is Bastion / Jump Server 

        
        -> A bastion host (often called a jump server or jump box) is a highly secured server 
        specifically designed to withstand cyber attacks. It acts as a dedicated gateway, 
        allowing administrators to safely access private, isolated network resources 
        from an external network like the public internet. 

        -> Backend servers, like databases or internal application servers, 
        are kept in private subnets without direct internet access for security. 
        A bastion host solves the access problem without exposing those backend servers 
        to threats.

        -> NOTE: A Bastion acts as a portal to private Virtual Machines

        -> How does it work ? 
        
            -> An administrator connects to the bastion host from an 
            external computer using a secure protocol like SSH (for Linux) or RDP (for Windows).
            
            -> Once authenticated and inside the bastion host, the administrator uses it 
            as a "stepping stone" to log into the private internal servers.
            
            -> The internal servers remain completely hidden from the internet.

            -> https://discover.strongdm.com/hs-fs/hubfs/Imported_Blog_Media/605d2e18679dad4a2e0b7df4_StrongDM-1-AWS-bastion-host-user-flow-2.jpg?width=780&height=438&name=605d2e18679dad4a2e0b7df4_StrongDM-1-AWS-bastion-host-user-flow-2.jpg

            -> https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcT03rna3SEB9qtGTghyNbQ6yukX9ALmsmSlKr_w9MMw_Fjac5swhOq76QJk&s=10

        
        -> We Can Setup Bastion Manually By Creating VM or Use Azure Provided Bastion Service.

            -> A bastion host is a traditional, self-managed virtual machine 
            used as a secure gateway to access a private network. 
            
            -> Azure Bastion is a fully managed, cloud-native PaaS (Platform-as-a-Service) 
            offered by Microsoft that replaces the need to 
            manually build, patch, and maintain your own bastion VMs.
